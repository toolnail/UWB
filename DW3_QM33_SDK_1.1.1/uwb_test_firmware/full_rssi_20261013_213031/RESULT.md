# 全量逐包 RSSI 文件记录

本次修改保留原有终端输出、RTT 通道 0 文本、每 1000 个唯一成功包的抽样日志、无线帧格式和 500 μs 发送延迟。新增 RTT 通道 1，以 16 字节记录独立保存 sequence、reception_id、RSSI/首径功率 Q8.8、有效标记和重复包标记。逐包记录由主循环使用同一帧保存的诊断/DGC 生成，接收中断不打印长文本。

## 使用

继续运行项目根目录的 `repeat_300k.cmd`。每轮新增：

- `round_1.rx.rssi.csv`：完整逐次成功 DATA 接收明细，可按 sequence 或 reception_id 处理。
- `round_1.rx.rssi.bin`：原始二进制记录，保留复核依据。
- `round_1.rx.rssi.capture.json`：完整性检查、总记录数、唯一包数、重复包数和传输丢弃数。

原来的 `round_1.rx.signal.csv` 仍然只有抽样明细。CSV 中 `rssi_dbm` 使用保存的 Q8.8 值转换，不以额外的小数位承诺硬件精度；`rssi_q8` 保留原始定点值。无效诊断写 `NA`；重复 DATA 保留单独的 reception_id 和 duplicate 标记；END 和 CRC 错误事件不是成功 DATA 行。

## 完整性与性能

板内二进制通道有 32 KiB 缓冲区，使用非阻塞模式，写入失败明确计数而不暂停接收。电脑在一个 RX J-Link 会话中同时采集两个通道，连接握手使用 100 kHz，数据传输使用 1 MHz；不增加终端输出。

文件只在 START/END、生成数量、保存数量、序号去重、接收编号、有效/无效诊断和原有固件汇总全部一致且通道丢弃为零时正式命名为 `.rx.rssi.csv`。失败保留 `.partial.csv`，脚本报错，避免把不完整数据当作完整文件。更高发送速率或采集进程停止仍可能导致通道溢出，完整性检查会拒绝该轮结果。
