# DWM3000 点对点“5 个 9”可靠性实验

## 1. 实验目标

验证当前 TX -> RX 单向链路的数据包正确交付率是否达到 99.999%。

本实验按目标序号统计唯一且内容校验正确的数据包。未成功交付的目标序号计为失败；`invalid` 和 `phy_err` 另外报告用于诊断。PHY 错误事件可能与序号缺失对应同一个包，因此不直接把事件数累加到失败包数中，避免重复计数。

## 2. 严格通过判据

- 发送 300,000 个带连续 32 位序号的数据包；
- RX 必须成功校验全部 300,000 个唯一数据序号；
- `failed = target - success` 必须为 0，最终报告 `success_ppm=1000000`；
- 程序最终输出 `RX_COMPLETE RESULT=PASS_95CI`。

当 300,000 次独立试验中观察到零次失败时，失败概率的单侧 95% 置信上限约为：

`-ln(0.05) / 300000 = 9.986 ppm`

因此这个判据可以在单侧 95% 置信水平下支持成功率至少为 99.999%。仅以 100,000 包零丢包计算经验成功率并不足以给出同样的统计置信度。

## 3. 本轮配置

- UWB 信道：5
- PRF：64 MHz
- 前导码：128 symbols
- 数据率：6.8 Mbit/s
- 测试负载：32 bytes，包含魔数、帧类型、32 位序号和确定性校验图样
- 发包间隔：10 ms
- 正常测试时长：约 50--55 分钟
- 数据方向：J-Link 1050244938（TX）到 J-Link 1050238642（RX）
- 正式启动时间：2026-09-29 15:20:11（Asia/Shanghai）

## 4. 当前运行文件

- TX 固件：`nrf52840_dwm3000_5nines_tx.hex`
- RX 固件：`nrf52840_dwm3000_5nines_rx.hex`
- TX 监控：`monitor_5nines_tx.ps1`
- RX 监控：`monitor_5nines_rx.ps1`
- 日志：`5nines_tx_live_*.log`、`5nines_rx_live_*.log`

监控程序只读取 RTT 输出；关闭监控窗口不会停止板内程序。断电、复位或重新烧录会重启本轮计数。

## 5. 结果解释

- `RESULT=PASS_95CI`：本轮全部目标序号都至少成功交付一次；
- `RESULT=FAIL`：`failed` 大于 0，即至少一个目标序号未成功交付；
- `success_ppm`：`success / target × 1,000,000`；`success` 按唯一序号计数，因此重复包不会提高成功率；
- `phy_err`：接收机报告的物理层错误事件数，作为诊断字段单独输出。若它导致某个测试包未成功交付，该序号会体现在 `failed` 中；事件数不与 `failed` 相加。

本轮只能代表当前距离、摆放、遮挡和干扰条件下的 TX -> RX 单向链路。若要声明系统级、双向或全工作范围达到五个九，还应交换 TX/RX 角色，并分别在目标距离、方向、遮挡、温度、电源条件和干扰场景下重复实验。
